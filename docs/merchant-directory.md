# Public merchant directory

Mahally/Salla merchant websites may supply public business-directory contacts without a separate outreach-consent grant. This policy is limited to merchants whose store ID and real website domain are bound by the Mahally product response. Explicit telephone/WhatsApp contact links on that same domain qualify; unrelated page text and reviewer phone numbers do not. Saudi-mobile validation and one-store/one-distinct-phone deduplication remain in force. These are product-selling stores, not confirmed buyers.

`wasla_merchant_directory` stores workspace-scoped publication evidence, source URLs, phone hashes and a 30-day freshness window. It is separate from `wasla_contact_authorizations`; publication never creates a consent record. The existing authorizer consults current publication evidence for save/reveal/download. Calling still requires a verified calling grant. Existing subject revocation also creates a directory suppression record, which rediscovery cannot overwrite. All authorization decisions are audited.

Apply `20261025_merchant_directory.sql` before activating. Configure the ignored, mode-600 `.env.mahally` with `MAHALLY_ENABLED=true`, `MAHALLY_PUBLIC_DIRECTORY=true`, the internal worker URL and a random 32-byte token. Both services read this file. Use `bun scripts/check-mahally-deployment.mjs --activate` to preserve current model settings and refuse activation while Lite searches run or unrelated backend settings differ. The worker is private-network only and Chromium remains sandboxed.

Validation: `scripts/run-contact-consent-postgres.mjs` tests real isolated database save/billing/reveal/download, denied calling, expiry, workspace/provider isolation and revocation without creating production consent records. `scripts/smoke-mahally-directory.mjs` checks a single live merchant and prints counts only; it saves no leads and incurs no lead charges. Live availability and the requested quantity are not guaranteed.
